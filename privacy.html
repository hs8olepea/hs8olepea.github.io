สิ่งที่เปลี่ยน: เพิ่มเซิร์ฟเวอร์ตรวจสิทธิ์ทดลองใช้ขนาดเล็กของผู้พัฒนา ซึ่งรับเฉพาะรหัสย่อประจำเครื่อง (ไม่มีอีเมล ไม่มีข้อมูลร้าน) ตอนเริ่มทดลองใช้ฟรี • What changed: added a small trial-check server run by the developer; it receives only the short device code (no e-mail, no shop data) when a free trial starts.

สรุปสั้นๆ

ข้อมูลของร้านอยู่ในมือถือของร้าน และใน Google Drive ของร้านเท่านั้น ผู้พัฒนาไม่เก็บและไม่ได้รับข้อมูลการขาย ลูกค้า หรือสต็อกของร้าน มีเพียงเซิร์ฟเวอร์ตรวจสิทธิ์ทดลองใช้ขนาดเล็กที่รับเฉพาะรหัสย่อประจำเครื่อง (ไม่มีอีเมล) ตอนเริ่มทดลองใช้ฟรีเท่านั้น แอปไม่มีโฆษณาและไม่มีระบบติดตามการใช้งาน

ข้อมูลที่แอปเก็บ

  • ข้อมูลร้าน: สินค้า สต็อก การขาย ใบเสร็จ ใบเสนอราคา ค่าใช้จ่าย ข้อมูลลูกค้าของร้าน (ชื่อ เบอร์โทร ที่อยู่ ทะเบียนรถ) และรูปถ่ายที่ร้านแนบไว้ ข้อมูลทั้งหมดเก็บในพื้นที่ของแอปบนมือถือเครื่องนั้น
  • ข้อมูลในเครื่อง: รหัส PIN สำหรับล็อกแอป รหัสเปิดใช้งาน วันเริ่มทดลองใช้ และบันทึกข้อผิดพลาดล่าสุดของแอป
  • รหัสย่อประจำเครื่อง: เพื่อให้แอปรู้ว่ามือถือเครื่องนี้เป็นเครื่องเดิมเมื่อถอนการติดตั้งแล้วติดตั้งใหม่ (และไม่นับเป็นการย้ายไปใช้เครื่องอื่น) แอปคำนวณรหัสย่อ 16 ตัวอักษรจากรหัสประจำเครื่องของระบบ Android ด้วยการแฮชทางเดียว (SHA-256) แล้วเก็บเฉพาะรหัสย่อนี้ แอปไม่เก็บและไม่ส่งรหัสประจำเครื่องจริง รหัสย่อแปลงกลับเป็นรหัสจริงไม่ได้ และไม่มีข้อมูลส่วนบุคคลอื่นปนอยู่ รหัสย่อนี้ถูกส่งไปเซิร์ฟเวอร์ตรวจสิทธิ์ทดลองใช้ด้วย (ดูหัวข้อ “เซิร์ฟเวอร์ตรวจสิทธิ์ทดลองใช้”)

การใช้บัญชี Google และ Google Drive

เมื่อร้านกด "เชื่อมบัญชี Google" แอปจะขอสิทธิ์ drive.file ซึ่งให้แอปเห็นและแก้ไขเฉพาะไฟล์ที่แอปสร้างเองเท่านั้น แอปมองไม่เห็นไฟล์อื่นใน Drive ของร้าน แอปใช้สิทธิ์นี้เพื่อ:

  • อ่านอีเมลของบัญชี Google เพื่อผูกกับรหัสเปิดใช้งานและช่วงทดลองใช้
  • สร้างโฟลเดอร์ "Battery POS Backup" และสำรองข้อมูลร้านลงไปวันละครั้ง (เก็บ 30 ไฟล์ล่าสุด) และกู้คืนจากไฟล์เหล่านั้นเมื่อร้านสั่ง
  • เก็บไฟล์ควบคุมขนาดเล็กในโฟลเดอร์เดียวกัน ได้แก่
    • device-lock.json เครื่องที่ใช้งานอยู่ขณะนี้: ชื่อรุ่นมือถือ รหัสสุ่มของแอปบนเครื่องนั้น รหัสย่อประจำเครื่อง อีเมลบัญชี และเวลาที่ย้ายเครื่อง
    • device-history.json ประวัติเวลาที่ย้ายเครื่อง (ไม่เกิน 10 ครั้งล่าสุด) ชื่อรุ่นและรหัสย่อของเครื่องล่าสุด และรหัสปลดล็อกที่ใช้ไปแล้ว เพื่อบังคับกติกาย้ายเครื่องได้ไม่เกิน 3 ครั้งใน 30 วัน
    • activation.txt สำเนารหัสเปิดใช้งาน และ trial.json วันเริ่มทดลองใช้

โฟลเดอร์และไฟล์เหล่านี้อยู่ใน Google Drive ของร้านเอง ร้านมองเห็น เปิดดู ลบ หรือแชร์ได้ ผู้พัฒนาไม่ได้รับสำเนาและเข้าถึงไม่ได้ ถ้าร้านลบไฟล์ควบคุม การย้ายไปใช้เครื่องใหม่อาจต้องขอรหัสปลดล็อกจากผู้ขาย

ข้อมูลจาก Google ใช้เพื่อการทำงานข้างต้นภายในแอปเท่านั้น ไม่ส่งต่อ ไม่ขาย และไม่ใช้เพื่อโฆษณา

เซิร์ฟเวอร์ตรวจสิทธิ์ทดลองใช้

เพื่อให้ช่วงทดลองใช้ฟรี 30 วันนับต่อมือถือหนึ่งเครื่อง (เปลี่ยนบัญชี Google บนมือถือเครื่องเดิมไม่ได้ทดลองใหม่) ผู้พัฒนามีเซิร์ฟเวอร์ตรวจสิทธิ์ขนาดเล็กที่ batterypos.duckdns.org แยกจากข้อมูลร้านค้าโดยสิ้นเชิง ทำงานดังนี้

  • เมื่อไหร่: เฉพาะตอนเริ่มทดลองใช้ฟรี (และลองใหม่เบื้องหลังถ้าเซิร์ฟเวอร์ติดต่อไม่ได้ครั้งแรก) ผู้ที่เปิดใช้งานด้วยรหัสแล้วไม่ส่งอะไรเลย
  • ข้อมูลที่ส่ง: รหัสย่อประจำเครื่อง (16 ตัวอักษร) วันเริ่มทดลองใช้ที่แอปทราบอยู่แล้ว (ถ้ามี) รุ่นของแอป และค่าสุ่มครั้งเดียวเพื่อกันการตอบซ้ำ ไม่ส่งอีเมล ไม่ส่งข้อมูลร้านค้า ลูกค้า การขาย หรือสต็อก
  • ข้อมูลที่เซิร์ฟเวอร์เก็บ: รหัสย่อประจำเครื่อง เวลาที่เห็นเครื่องนี้ครั้งแรก เวลาล่าสุด จำนวนครั้งที่ตรวจ และรุ่นแอป ไม่เก็บอีเมลหรือที่อยู่ IP ในฐานข้อมูล และตั้งค่าไม่ให้เว็บเซิร์ฟเวอร์บันทึกการเข้าถึงสำหรับบริการนี้ บันทึกข้อผิดพลาดของเว็บเซิร์ฟเวอร์ (เช่น เมื่อมีคำขอถี่ผิดปกติ) อาจมีที่อยู่ IP ชั่วคราวและถูกลบอัตโนมัติภายใน 14 วัน
  • วัตถุประสงค์: จำกัดการทดลองใช้ฟรีหนึ่งครั้งต่อมือถือหนึ่งเครื่องเท่านั้น ไม่ใช้เพื่อโฆษณา ไม่ติดตามการใช้งาน ไม่ขาย และไม่ส่งต่อให้ผู้อื่น

  • ถ้าเซิร์ฟเวอร์ใช้ไม่ได้: แอปใช้งานต่อได้ตามปกติ (ใช้วันเริ่มทดลองที่เก็บใน Google Drive ของร้าน) แล้วตรวจอีกครั้งภายหลัง

Summary

Battery POS keeps shop data on the shop's own phone and in the shop's own Google Drive. The developer does not store or receive sales, customer or stock data. The only server is a small trial-check server that receives just the short device code (no e-mail) when a free trial starts. The app has no ads and no analytics.

Data the app stores

  • Shop data: products, stock, sales, receipts, quotations, expenses, the shop's customer details (name, phone, address, licence plate) and photos the shop attaches. All of it is kept in the app's storage on that phone.
  • On-device settings: the app PIN, the activation code, the trial start date, and a short log of recent app errors.
  • Short device code: so that the app can recognise the same phone after an uninstall and reinstall (and not count it as moving to another device), the app computes a 16-character short code from the Android system device identifier using a one-way hash (SHA-256) and stores only that short code. The raw identifier is neither stored nor sent anywhere. The short code cannot be converted back to the raw identifier and contains no other personal data. It is also sent to the trial-check server (see "Trial-check server").

Google account and Google Drive

When the shop taps "Connect Google account", the app requests the drive.file scope, which only gives access to files the app itself created. The app cannot see any other files in the shop's Drive. The app uses this access to:

  • read the Google account's email address, to bind it to the activation code and the free trial;
  • create a "Battery POS Backup" folder, upload a daily backup there (keeping the latest 30), and restore from those files when the shop asks;
  • keep small control files in the same folder:
    • device-lock.json — the device currently in use: phone model name, the app's random installation ID on that device, the short device code, the account email and the time of the last move;
    • device-history.json — the times of the last 10 device moves, the model name and short code of the latest device, and the unlock codes already used, to enforce the rule of at most 3 device moves per 30 days;
    • activation.txt — a copy of the activation code, and trial.json — the trial start date.

This folder and these files are in the shop's own Google Drive: the shop can see, open, delete or share them. The developer receives no copy and has no access to them. If the shop deletes the control files, moving to a new device may require an unlock code from the seller.

Battery POS's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. Google user data is used only to provide the features above. It is not transferred, sold, or used for advertising.

Trial-check server

So that the 30-day free trial counts once per phone (switching Google account on the same phone does not start a new trial), the developer runs a small trial-check server at batterypos.duckdns.org, completely separate from the shops' data:

  • When: only when a free trial starts (and retried in the background if the server could not be reached the first time). Shops that have activated the app with a code send nothing.
  • What is sent: the 16-character short device code, the trial start date the app already knows (if any), the app version, and a one-time random value to prevent replay. No e-mail, and no shop, customer, sales or stock data.
  • What the server stores: the short device code, the time it was first seen, the last time, the number of checks, and the app version. No e-mail or IP address in the database, and the web server is configured not to write an access log for this service. The web server's error log (for example when requests are unusually frequent) may contain an IP address temporarily and is deleted automatically within 14 days.
  • Purpose: to allow one free trial per phone. Not used for advertising or tracking, not sold, not shared.
  • Retention: deleted automatically when the device has not been checked for 24 months.
  • If the server is unavailable: the app keeps working normally (using the trial start stored in the shop's Google Drive) and checks again later.
  • Deletion on request: contact the developer with the device code (shown in the app's support report, line "device code") to delete that device's record (afterwards that device may be able to start a new free trial).

Data sent to the developer

Apart from the trial-check server above, the app sends nothing to the developer on its own. If the shop taps "Send to seller" in Settings, the app builds a text summary and opens the phone's share sheet, and the shop chooses where to send it, for example LINE. The summary contains the app version, phone model, the device code and trial-check status, Google account email, activation status, last backup time and recent errors. It contains no sales, customer or stock data, and the shop can review it first with "Show what will be sent".

If a shop chooses to send a backup file for help with a problem, the developer uses it only to fix that problem and deletes it afterwards.

Deleting data and revoking access

  • On the phone: uninstall the app, or clear the app's data in Android settings.
  • In Drive: delete the "Battery POS Backup" folder from the shop's Google Drive (this includes device-lock.json and device-history.json inside it).
  • To revoke access, go to myaccount.google.com/permissions and remove Battery POS, or tap "Disconnect" in the app.
